# Changelog — services/worker

All notable changes to this module. Versioning policy: `docs/guides/versioning.md`. A change that removes or alters an exported identifier, or alters behaviour this module's README documents, is a major-version change once the module is being tagged.

## [Unreleased]

- Added (Phase 4, ADR-0031): `archive` (the `audit-archiver` consumer: every `libs/events` type to MongoDB `events`, audit records for role changes, publish and archive; idempotent by event id), `deadletter` (`Sink` parks events a consumer gave up on, bounded and idempotent per event and consumer; `Replayer` re-applies a parked event through the consumer's own handler with its `processed_events` marker and marks it replayed exactly once) and `admin` (HTTP on `ADMIN_HTTP_ADDR`, default `:8093`: health and the admin-only failed-events list, detail and replay). `cmd/worker/mongo_wire.go` connects MongoDB in the background (unset or unreachable: the worker still starts, logs loudly, archive and replay degrade) and runs the admin server as a fifth goroutine that never stops the relay. `consumerHandlers()` is now the single list `buildRelay` registers and the Replayer replays through. The archiver and the Sink are **not** registered with any transport yet (kafka-mode wiring, see `archive/README.md`). `go.mod` requires `libs/events`, `libs/mongostore` (and now directly `libs/auth`, `libs/httpx`, `libs/router`, `libs/errors`); `Dockerfile.worker` copies the two new modules.
- Added the Kafka event transport (ADR-0029, `EVENT_TRANSPORT=kafka`; the default `inprocess` behaves as before). New package `transport`: the relay's `Publisher` (outbox row to registry-framed Envelope, routed by event-type prefix, keyed by `aggregate_id`, acknowledged before the row is marked published), the consumer `Runner` (one group per consumer name, same handlers through `relay.Deliver`, parks exhausted records through the dead-letter sink), `Prepare` (topic provisioning and a schema-registry check at start), and `transporttest.Registry` (a stand-in registry for tests). New `cmd/worker/transport.go`: `transportMode(cfg)`, `newEventTransport(ctx, logger, cfg, sink)` with `RelayOptions()`, `Run`, `HealthCheck()` (the non-fatal Kafka readiness check; the worker has no HTTP surface yet, so nothing serves it) and `Close()`. `buildRelay` takes optional `relay.Option`s; `main` starts the consumers as a fourth goroutine. The worker's two end-to-end tests now run under both transports. `go.mod` requires `libs/events` and `libs/kafka`; the Dockerfile copies them.

- Added the `notification` package (notification-dispatcher, ADR-0014): relay handlers for `identity.user_registered`, `identity.user_profile_updated`, `enrollment.student_enrolled`, `progress.course_completed` and `course.course_published` that write a recipient mirror and one delivery record per (event, kind, recipient) in the new `notification` schema (`migrations/notification`); `EnqueuePending`/`RunSweeper`, which hand pending deliveries to an `Enqueuer` and recover a crash between commit and enqueue; `NewDeliveryHandler` and `TaskTypeDeliver` (`notification:deliver`) for the queue task; a `Provider` interface with an SMTP implementation (net/smtp, STARTTLS and auth supported, aimed at Mailpit); escaped text and HTML templates. Not wired into `cmd/worker` yet: see the package README. No change to existing exports. The rare duplicate send (sent but not marked) is documented there, not denied.
- Worker wiring (docs/plans/week-3.md wiring backlog 1 and 3): the Temporal worker's course service now has the asset store attached as course-api does (`newCourseService`); `RELAY_WORKERS` reaches the relay (`buildRelay` now takes the config); Asynq runs as a third goroutine, one server per queue with RFC §10.2's pools (`ASYNQ_*_CONCURRENCY`) and a scheduler. An Asynq or scheduler failure is logged and does not stop the relay or the Temporal worker.
- New package `jobs`: scheduled maintenance jobs on the `low` queue: stale-publish reconciliation (`ReconcileStalePublishes`, every minute), analytics reconciliation through a `Runner` interface (every minute; not scheduled until `analyticsReconciler` in `wire.go` returns one), enrollment counter repair, idempotency-key pruning, outbox pruning (`OUTBOX_RETENTION`, default 7 days). Intervals are configurable (`JOBS_*_INTERVAL`).
- `go.mod`: requires `libs/asynqx` and `libs/idempotency`; the Dockerfile copies `libs/asynqx`.

- Security: bumped indirect dependencies to clear govulncheck findings reachable from this module's code (golang.org/x/net v0.58.0 to v0.60.0 and github.com/quic-go/quic-go v0.59.0 to v0.59.1 where present; github.com/moby/go-archive v0.2.0 to v0.3.0, github.com/klauspost/compress v1.18.6 to v1.20.2 and github.com/moby/sys/user v0.4.0 to v0.4.1 where present, test-only via testcontainers). No API change.
