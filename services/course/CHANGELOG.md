# Changelog — services/course

All notable changes to this module. Versioning policy: `docs/guides/versioning.md`. A change that removes or alters an exported identifier, or alters behaviour this module's README documents, is a major-version change once the module is being tagged.

## [Unreleased]

- Added the three events RFC §6.5 listed but nothing emitted (DR-026): `progress.lesson_completed` (`progress`, written once per lesson completion, not on an idempotent repeat), `progress.certificate_issued` (`certificate`, in the certificate's transaction, no verification code) and `course.publish_failed` (`course`, in the transaction that moves a version to `publish_failed`, from the workflow failure step and the stale-publish reconciler, once per failure; reason cut to 500 characters). Typed payload structs (`LessonCompletedPayload`, `CourseCompletedPayload`, `CertificateIssuedPayload`, `PublishFailedPayload`) replace `map[string]any` for them; `services/worker`'s payload contract test pins them to the schemas. Events are new-only: earlier completions, certificates and failures have none.
- Changed (exported API): `course.Service.MarkPublishFailed` and `workflows.Activities.MarkPublishFailed` take the failed activity's name as a last argument; `Repository.FailVersion` (new) only transitions a version that is not already `publish_failed`. In-flight workflows scheduled with the old two-argument activity were not tested across the change.

- course-api wires telemetry in `cmd/course-api/main.go`: tracing (with the Temporal client interceptor), RED metrics, `/metrics`, outbox gauges, bounded flush on shutdown (Phase 7).

- Added package `services/course/certificate` (RFC §8.4): `Handlers()` returns a `libs/relay` handler (consumer `certificate-issuer`) that issues one certificate per enrollment from `progress.course_completed`, idempotent under duplicate and concurrent delivery (`UNIQUE (enrollment_id)` with `ON CONFLICT DO NOTHING`; `processed_events` is the second line). The title and student name are snapshotted (name from `instructor_mirror`, never from the identity schema). An event for an unknown or withdrawn enrollment, or whose `student_id` does not match, is acknowledged with a logged reason; a student whose name is not mirrored yet returns an error so the relay retries. Certificates are never revoked, including when a republish moves a completed enrollment back to active (RFC §8.3/§8.4, A5). `RegisterRoutes(r, svc, jwtCfg, publicMW...)` adds `GET /certificates`, `GET /certificates/{id}` (owner only, non-owner 404) and the public `GET /certificates/verify/{code}`. `course-api` wires them, with a 30 per minute per-IP limit on the public route, and now requires `libs/ratelimit`. The worker must register `certificate.Handlers()`; nothing does yet. Needs migration `migrations/course/000007_certificates` (adds `student_id`, `course_id`, `course_version_id`, a code-format CHECK and indexes to the `certificates` table from 000003).
- Added `enrollment.ReconcileEnrollmentCounts(ctx, db)` (new file `enrollment/reconcile.go`): recomputes `courses.enrollment_count` from the enrollments that are not withdrawn and rewrites any counter that disagrees, one transaction per course that locks the course row first (ADR-0012). `completed` enrollments keep their seat, matching `Enroll`/`Withdraw`. The worker schedules it (RFC §9.5). It is exported but nothing in course-api calls it.

- `Idempotency-Key` is honoured on the `POST` routes (create course, add module, add lesson, publish, archive, `POST /assets/upload-url`, `POST /enrollments`) through `libs/idempotency`; `RegisterRoutes` in `course` and `enrollment` take optional per-`POST` middleware. Behaviour with no middleware passed is unchanged (DR-023).
- Added `POST /assets/upload-url` (instructor who owns the course): a 15-minute pre-signed PUT URL for a server-generated object key scoped to the course (and optionally a draft lesson), with a content-type allowlist and per-type maximum size signed into the URL. New package `services/course/assets` (AWS SDK for Go v2 S3 client, `service/s3` v1.115.0, Apache-2.0, pure Go) implements the new `course.AssetStore` interface; attach it with `Service.WithAssetStore`. New `invalid_asset_key`, `unsupported_content_type`, `asset_too_large`, `assets_unavailable` and `asset_invalid` error codes.
- `VerifyAssets` now checks every lesson `asset_key` against object storage (exists, non-empty, size and content type within the allowlist, key scoped to the same course) and fails the publish cleanly when one is missing or invalid; lessons without an asset are unaffected. Behaviour change: `AddLesson` rejects an `asset_key` that is not a key issued for the course (400 `invalid_asset_key`), and a service with no asset store fails a publish whose lessons reference assets. The worker must call `WithAssetStore` for `VerifyAssets` to run there.

- The `course.course_published` outbox payload gains `instructor_id` (additive; schema_version unchanged). Existing consumers decode only the fields they use, so analytics is unaffected (checked against its handler).

- Added `Service.ReconcileStalePublishes(ctx)`: releases a version stuck `publishing` (claim older than one minute) whose Temporal workflow is not running, to `publish_failed` with an explanatory `publish_error`, so a crash between claim and workflow start no longer blocks republishing for the 15-minute lease. Guarded on the same claim, so a concurrent legitimate completion is never overwritten; idempotent. Not scheduled yet: the worker or an Asynq job must call it. Adds `go.temporal.io/api` as a direct dependency.

- Security: bumped indirect dependencies to clear govulncheck findings reachable from this module's code (golang.org/x/net v0.58.0 to v0.60.0 and github.com/quic-go/quic-go v0.59.0 to v0.59.1 where present; github.com/moby/go-archive v0.2.0 to v0.3.0, github.com/klauspost/compress v1.18.6 to v1.20.2 and github.com/moby/sys/user v0.4.0 to v0.4.1 where present, test-only via testcontainers). No API change.

- `POST /courses/{id}/publish` claims the draft (state `publishing`) before starting the workflow. A duplicate while a publish is running now returns **409 `publish_in_progress`** (was 202 attaching to the running workflow); a failed workflow start releases the claim; a claim older than 15 minutes may be reclaimed. Fixes a race where a fast-failing workflow's `publish_failed` could be overwritten with `publishing` (F-37, ADR-0028). Needs migration `migrations/course/000006_publish_started_at`.

- Fixed (F-01, F-06, F-07, F-08, F-10, F-11, F-17, F-20, F-21, F-22, F-23, F-25, F-27, F-36): see `docs/plans/module-split-findings.md`. Behaviour changes: non-owner access to an existing course now returns 404 `not_found` (was 403 `not_owner`); publishing an archived course returns 409 `course_archived`; `ValidateMetadata` requires a lesson; deleting a module/lesson of a non-draft version returns 409 `no_draft`; `MarkComplete` for a lesson not in the published version returns 404 `lesson_not_found`; instructor write routes enforce the token-version check; NUL bytes, deeply nested content and out-of-range integers return 400.
