## Observations (no reproducer, and why)

1. **Strict unknown fields make rolling deploys dead-letter events.** `Encode` uses `protojson.UnmarshalOptions{}` (no `DiscardUnknown`), and the test `TestCodec_UnencodableRowsAreMarkedAndNamed` asserts that a field not in the schema is unencodable, so this is a deliberate choice. Consequence: an API at the new version writing a new field while an old worker relays is parked after the retry budget, event by event. A design trade-off, not a defect; no reproducer because the existing test pins the behaviour. Worth an ADR line.
2. **A hot aggregate serialises.** Publish mode claims a row only if no earlier unpublished row of the same `aggregate_id` exists. `student_enrolled` rows carry the course as aggregate (the test comments say so), so every enrollment of one course publishes one at a time at broker-ack latency. Correct for order; throughput under E09-style load per course was not measured.
3. **Lease takeover can run an idempotent request twice.** `idempotency` takes over an `in_progress` key after the 3-minute lease while the original owner may still be running (the lease is not enforced as a deadline on the owner). The window needs a handler longer than the lease; DR-022 caps requests at 120 s. No reproducer because it needs a handler that violates that cap.
4. **A Redis flush costs queued notification tasks up to `RequeueAfter` (5 min)**; the sweeper recovers them. Bounded and documented in `notification/dispatcher.go`; not measured end to end.
5. **Scheduler tick labels with a replica clock skew above `TickSkewTolerance` (10 s).** A cron timer that fires more than 10 s late labels itself with the next slot, so one tick can run twice within seconds and the next be deduplicated away. Harmless for the idempotent maintenance jobs; needs an injectable clock to test, which `fire` does not have.
6. **Replay is not audit-logged** (ADR-0031 says so itself); not re-tested.
7. **Duplicate-send window.** The delivery handler documents it (mail sent, mark fails, lease 5 min, then a second mail). Not exercised end to end because the lease is not configurable in the e2e worker; the replica test saw 0 duplicates of 18.
8. **`outbox` rows given up with a sink keep `last_error` and so are never pruned either**; by design (the comment says they are the only record), but with a working sink the parked copy exists and the keep rule is redundant. Folds into B-09's fix.
9. **A record exhausted while the consumer is shutting down** passes `ctx` already cancelled to the sink; `Sink.Park` detaches from cancellation, so this is fine for the real sink; a different `DeadLetterSink` implementation would see a cancelled context. Contract note only.

## Where existing tests do not prove what they claim

1. **E13 hides B-06.** `TestE2E_E13_ArchiveAndAudit` sets `KAFKA_CONSUMER_MAX_ATTEMPTS=12` and a 2 s backoff cap "long enough to outlast the MongoDB outage in step 6". The outage is shorter than the budget by construction, so the test cannot show what happens when it is not. Missing test added: B-06/B-07.
2. **E13's "types the spec lists that no service emits" subtest always skips** (`t.Skipf` is unconditional after the lookup), although `progress.lesson_completed`, `progress.certificate_issued` and `course.publish_failed` are now in the catalogue and emitted. Archive completeness for those three is asserted only through the generic per-outbox-row loop; the subtest's claim ("no service emits them") is stale.
3. **The transport integration tests prove the transport with a synthetic handler.** `effectHandler` writes to a test table (`public.test_effects`) under invented consumer names, and the payloads in `samplePayloads` are hand-written copies of what the services write. They do prove order and duplicates for the transport; they do not prove the real handlers' behaviour on Kafka-decoded payloads (that rests on the e2e tier) or that the writers' real structs match the schema (checked here by reading each `outbox.Write` call site; no test pins it). The round-trip test's `len(in) == len(out)` check also cannot see zero-value handling because every sample field is non-zero (B-04).
4. **Every Week 3 e2e scenario ran one worker.** Two replicas, which is what ADR-0027/0029 and the scheduler dedupe design exist for, were never exercised together before the new replica test.

## Not covered

Postgres stopped and restarted (the harness has no helper); Temporal stopped mid-publish (E12 covers faults, not a stopped server); connection-pool exhaustion with `RELAY_WORKERS`, Asynq pools and handlers all busy (startup guard only read, not stressed); the 15 MiB payload cap and a very large parked set (pagination, memory; the list uses a keyset cursor, only read); two real consumers rebalancing during a side-effecting handler (E06 kills, it does not rebalance); malformed, zero and over-long outbox trace ids end to end (code read, fuzzed at the codec only); schema_version skew between producer and consumer; Mongo up but the replay's mark failing; two admins replaying the same event through the admin HTTP API (the Replayer level is covered by an existing test, not re-run); scheduler replicas with real clock skew; Redis flush mid-flow with queued Asynq tasks; analytics reconciliation under heavy writes (read `reconcile.go` and `enrollment/reconcile.go`, both lock per course and recheck; not stressed); `services/identity` security suites and E01 to E14 were not re-run; the `libs/events` registry `live` tests.
